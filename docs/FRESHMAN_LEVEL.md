# Campus Runner — 1학년 1학기 학점 아이템 조정

## 변경 범위와 유지 사항

이번 작업은 StageFactory.createFreshman()의 아이템 목록, FreshmanLevelVerification.java와 이 문서만 수정했다.
작업 시작 시 이미 존재하던 8학기 시스템 관련 미커밋 변경은 보존했다.
학점 아이템은 10개에서 4개로 줄였으며 각 5점, 최대 20점이다.
월드 너비 2400, 시작 (80,60), 깃발 (2360,360,20,100), 발판 10개의 좌표와 난이도는 유지한다.
Player(32×44, 이동 260, 점프 650, 중력 1700), Main, HUD, GameState, 점수 시스템은 수정하지 않았다.
2~8학기의 createTestStage 데이터와 8학기 진행 시스템도 유지한다.
1학기에 이동 발판·함정·적을 추가하지 않았다.

## 기존 맵 단순화 이력 (이번 작업에서 변경 없음)

이 표는 이전 맵 단순화 작업의 Rectangle 개수 비교이며, 바닥도 포함한다.
이번 아이템 조정에서는 현재 발판 10개를 모두 그대로 유지한다.
구간은 발판의 시작 x로 분류하고 바닥은 구간 경계를 넘어 이어진다.

| 구간 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| A (0~600) | 4 | 2 |
| B (600~1200) | 7 | 2 |
| C (1200~1800) | 10 | 2 |
| D (1800~2400) | 4 | 4 |
| 합계 | 25 | 10 |

15개(60%) 감소했다. 바닥은 7개에서 2개, 바닥 이외 발판은 18개에서 8개로 줄였다.
B/C 복귀 계단·상하 병렬 경로를 제거했다. C에도 연속된 안전 바닥이 있다.
D의 네 착지면은 고정된 높이 360의 깃발에 도달하는 데 사용한다.

## 모든 발판의 좌표와 목적

좌표는 왼쪽 아래 기준, 윗면은 y+높이다. 장식용 발판은 없다.

| 구간 | (x,y,너비,높이) | 윗면 | 플레이 목적 |
| --- | --- | ---: | --- |
| A~B | (0,0,780,60) | 60 | 안전한 시작, 걷기, 첫 틈의 도약 바닥 |
| A | (300,60,140,50) | 110 | 높이 50의 낮은 장애물로 기본 점프 연습 |
| B~D | (860,0,1040,60) | 60 | 첫 틈 착지, 선택 수집을 생략하는 연속 바닥, D 진입 |
| B | (1000,130,160,20) | 150 | 기존 선택 발판 유지; 바닥에서 한 번 점프 |
| C | (1300,120,160,20) | 140 | 선택 아이템 3 수집과 다음 발판의 도약대 |
| C | (1490,200,160,20) | 220 | 기존 선택 발판 유지; 오른쪽 바닥으로 하강 |
| D | (1800,120,150,20) | 140 | 마지막 상승 시작, 두 번째 틈을 건너는 도약대 |
| D | (1980,200,140,20) | 220 | 틈 건너 착지와 다음 상승 연결 |
| D | (2140,280,100,20) | 300 | 깃발 높이 360에 도달하는 마지막 도약대 |
| D | (2240,0,160,360) | 360 | 넓은 최종 착지면과 깃발까지 안전한 이동 |

A는 낮은 장애물, B는 짧은 틈과 선택 점프, C는 두 높이의 선택 수집,
D는 깃발을 향한 상승으로 구성한다. 바닥 틈은 B의 780~860, D의 1900~1980으로 각각 폭 80이다.
D 도약대는 틈 위로 50만큼 뻗어 실제 상단 사이 간격은 30이다.
필수 상승은 50·80·80·80·60, 선택 발판 진입의 최대 상승은 90이다.
B/C에서 떨어져도 별도 복귀 계단 없이 바닥에서 오른쪽으로 진행한다.
기본 경로와 전체 수집 모두 역주행하지 않는다.

## 학점 아이템

모두 24×24, 각 5점이다. 기본 경로 3개, 중간 선택 발판 1개다.

| 번호 | (x,y) | 수집 위치 |
| --- | --- | --- |
| 1 | (130,84) | 시작 바닥 |
| 2 | (520,84) | A 점프 후 바닥 |
| 3 | (1360,164) | C 중간 선택 발판 |
| 4 | (2310,384) | D 마지막 점프 후 깃발 착지면 |

3번을 생략해도 3개/15점으로 클리어한다. 전체 수집은 4개/20점이다.
아이템 수집은 클리어 조건이 아니며, 기존 점프 능력으로 4개 모두 수집할 수 있다.
아이템 수집에 긴 역주행이나 별도 정밀 점프가 필요하지 않다.

## 학기별 목표 개수와 점수·HUD

| 학기 | 향후 목표 아이템 수 | 최대 점수 (각 5점) |
| --- | ---: | ---: |
| 1학년 1학기 | 4 | 20 |
| 1학년 2학기 | 5 | 25 |
| 2학년 1학기 | 6 | 30 |
| 2학년 2학기 | 7 | 35 |
| 3학년 1학기 | 8 | 40 |
| 3학년 2학기 | 9 | 45 |
| 4학년 1학기 | 10 | 50 |
| 4학년 2학기 | 12 | 60 |

이번에는 첫 학기만 적용했다. 2~8학기는 현재 테스트 맵과 기존 아이템 10개를 유지하며,
각 학기를 제작할 때 위 목표를 적용한다. GPA 계산은 구현하지 않았다.

Main.renderHud()는 수집 개수와 현재 스테이지에서 로드한 gradeItems.size를 직접 표시한다.
따라서 시작 시 `ITEMS: 0 / 4`, 전체 수집 시 `ITEMS: 4 / 4`, `SCORE: 20`이 된다.
GradeItem은 각 5점을 누적하고, StageResult는 실제 점수와 수집 개수를 저장한다.
총점도 저장된 결과의 합계이므로 최대 50점 가정은 없으며 관련 코드를 수정할 필요가 없다.

## 실제 입력 검증 경로

아래 (x,윗면 y)의 x는 Player 왼쪽이다. 이동 후 입력을 놓고 착지를 기다린다.
완주 중 위치 재설정·아이템 상태 변경·깃발 강제 접촉을 사용하지 않는다.

- A: x240 → 점프(340,110) → 오른쪽으로 내려가 (520,60).
- B: x720 → 점프(890,60).
- 전체 수집: x940 → 점프(1050,150) → x1080 → 내려가 (1200,60)
  → x1240 → 점프(1350,140) → x1410 → 점프(1540,220)
  → x1570 → 내려가 (1710,60).
- 부분 수집: B 착지 후 바닥으로 x1710까지 이동. 높은 발판 아래로 통과한다.
- D 공통: x1740 → 점프(1850,140) → x1900 → 점프(2030,220)
  → x2070 → 점프(2170,300) → 점프(2290,360) → 깃발까지 이동.

별도 틈 검증에서는 초기 배치 후 실제 점프한다.
B는 출발 x700·720·740에서 (870,60), D는 x1870·1890·1910에서 (2000,220)에 착지한다.
각각 폭 40의 출발 범위를 세 FPS에서 검증한다.
두 틈 모두 바닥에서 틈 안까지 걸어가 수평 입력을 놓으면 실제 추락해 GAME_OVER가 된다.

## 빌드 및 검증 결과

JDK 17에서 `.\gradlew.bat build` 성공. 기존 check에 연결된 core:verifyFreshman으로 검증한다.

| FPS | 최대 상승 | 같은 높이 점프 이동 | 전체 수집(4개/20점) | 부분 수집(3개/15점) |
| --- | ---: | ---: | ---: | ---: |
| 30 | 113.67 | 190.67 | 10.27초 | 9.60초 |
| 60 | 118.86 | 195.00 | 10.50초 | 9.72초 |
| 120 | 121.56 | 197.17 | 10.51초 | 9.73초 |

시간은 판단·입력 준비·실패를 포함하지 않는 자동 입력 측정값이다. 초보자 플레이 시간은 미측정이다.

- 30·60·120fps에서 실제 Main/Player와 합성 방향키·Space 입력으로 두 경로 클리어.
- 4개/20점과 3개/15점, 선택 아이템 번호까지 확인.
- HUD 입력 데이터가 시작 시 0/4·0점, 전체 수집 시 4/4·20점인지 확인.
- 4개 수집 후 실패·Enter 재시작 시 같은 위치에 미수집 아이템 4개 복원, 점수 0점 확인.
- 점프 전 다음 착지 위치의 카메라 범위, 역주행 없는 이동, 실제 깃발 착지.
- 두 바닥 틈의 여러 출발 위치 점프 및 실제 추락 GAME_OVER.
- 정지/재개, 추락 후 Enter 재시작, 1학기 클리어 후 Enter로 2학기 전환과 20점 결과 보존.
- 2학기 진입 시 HUD 입력 데이터가 0/10·0점으로 바뀌는지 확인.
- 1~8학기 전환, 마지막 GAME_COMPLETE, 총점, 재도전 기록 보존, 새 게임 초기화.
- 2~8학기 기존 고정 발판·아이템 좌표, 월드·시작·깃발, 장애물 개수 유지.
- 아이템 5점·월드 범위·고정 블록 비중첩, 정의와 런타임 객체의 복사 독립성.

검증은 창을 열지 않고 렌더링을 실행하지 않는다. HUD는 실제 입력 데이터를 자동 검증하고
renderHud()의 동적 표시식을 소스에서 확인했다. GUI에서의 실제 문자열 렌더링은 미검증이다.
재시작 복원·학기 생명주기 검사에서는 아이템·깃발에
직접 배치하며, 2~8학기의 실제 입력 완주를 검증하는 것은 아니다.
GUI에서의 시인성·조작감·초보자 난도 플레이테스트는 미실행이다.
수동 확인은 `.\gradlew.bat lwjgl3:run`으로 실행해 A 점프, B/C 선택 수집과 바닥 통과,
D 상승과 깃발 착지, 카메라·HUD 가림 여부를 확인한다.

Git commit, push, merge는 실행하지 않았다.
