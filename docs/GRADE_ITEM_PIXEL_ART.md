## 이미지 크기와 정렬

원본은 128×128 RGBA 투명 PNG이며 A+ 금색 별과 작은 반짝임을 포함한다.
alpha가 0보다 큰 픽셀의 영역은 (20,8)~(111,105), 즉 92×98이다.
반짝임을 자르지 않고 PNG 전체를 **48×48 월드 단위**로 그린다.
가로세로 배율은 모두 0.375로 같으며 실제 보이는 부분은 약 **34.5×36.75**다.
이전 32×32 표시에서는 투명 여백 때문에 실제 그림이 약 23×24.5에 불과해 작아 보였다.
표시 크기를 키우고 기존 중심보다 10단위 내려 32×44 플레이어와 비교해 잘 보이도록 조정했다.

배치 좌표는 원래 충돌 사각형의 왼쪽 아래 좌표다. 그림의 수평 중심은 그 사각형과 같고,
수직 중심만 10단위 아래로 이동한다. 충돌 영역과 실제 배치 좌표는 변경하지 않는다.

```text
centerX = bounds.x + bounds.width / 2
centerY = bounds.y + bounds.height / 2
drawX = centerX - 24
drawY = centerY - 24 - 10
drawWidth = drawHeight = 48
```

예를 들어 Stage 1의 첫 아이템 (130,84), 충돌 크기 24×24의 중심은 (142,96)이다.
PNG는 (118,62)에 48×48로 그리고 시각적 중심은 (142,86)이다.
PNG의 아래쪽 투명 여백까지 고려한 실제 그림 하단은 약 Y=70.25로, 시작 바닥 윗면 Y=60과 약 10.25단위 간격이 있다.
표시 전용 `DRAW_SIZE=48`, `DRAW_OFFSET_Y=-10`은 충돌 사각형이나 배치 좌표를 변경하지 않는다.
회전·상하 이동·반짝임 애니메이션은 추가하지 않았다.

## 렌더링과 텍스처 수명

Main.create에서 `gradeItemTexture` 하나를 로드하고 min/mag 필터를 모두 TextureFilter.Nearest로 설정한다.
모든 학기·모든 GradeItem은 이 텍스처 참조를 공유한다. 아이템 생성·수집·사망·학기 전환 때 텍스처를 만들지 않는다.
Main.dispose에서 공통 텍스처를 한 번 해제한다.

GradeItem.render는 수집된 아이템이면 즉시 반환하고, 미수집 아이템만 그린다.
기존 월드 렌더 행렬을 사용하므로 카메라 이동과 피격 흔들림도 다른 월드 오브젝트와 동일하게 적용된다.
ShapeRenderer를 끝낸 뒤 SpriteBatch로 아이템을 그린다. 둘의 begin/end를 겹치지 않는다.
기존 아이템 표시 순서와 피격 캐릭터를 가장 위에 그리는 순서도 유지한다.

## 실제 GUI 확인

실제 LWJGL 창에서 **640×480·800×600·1280×720** 각각 다음 순서로 실행해 9개 화면을 캡처했다.

1. Stage 1의 첫 아이템 PNG·투명 배경·크기·중심을 확인.
2. 실제 오른쪽 이동 입력으로 아이템을 수집하고 지나간 뒤, 그림 제거·ITEMS 1/4·SCORE 5를 확인.
3. 추가 10프레임 동안 점수가 그대로인지 확인한 후, 낙사 위치 픽스처로 기존 사망/재시작을 실행.
4. ITEMS 0/4·SCORE 0·아이템 복구와 수집 전후 동일한 충돌 bounds를 확인.

48×48·Y -10 조정 후 이 검증을 다시 실행했다. 특히 800×600에서 플레이어 대비 별 크기,
A+ 가독성, 시작 바닥과의 간격을 직접 캡처로 확인했으며 과도한 겹침이 없었다.
아이템 영역의 픽셀 비교에도 새 표시 크기와 Y 오프셋을 반영했다.
`.\gradlew.bat build` 및 30·60·120fps 기존 전체 회귀 검증도 다시 통과했다.
이번 크기/위치 조정의 변경 파일은 GradeItem.java와 이 문서뿐이다.

아이템 화면 영역의 픽셀은 수집 후 달라지고, 재시작 후에는 최초 화면 영역과 완전히 일치했다.
세 창 크기와 재시작 동안 같은 Texture 객체를 유지하는지, 두 필터가 Nearest인지 확인했다.
GUI 도구에서도 8학기 개수·24×24 충돌 크기·305점 합계를 검사했고, 앱 종료 후 Texture GL 핸들 해제를 확인했다.
테스트 도구와 캡처는 build 디렉터리의 생성물이며 Git에 포함하지 않는다.
