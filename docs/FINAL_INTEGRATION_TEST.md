# Campus Runner — STEP 10-13 전체 통합 테스트

검증일: 2026-11-08. 범위는 기존 게임 안정성 검증과 명확한 오류 확인이다. 레벨·난이도·점수·GPA·미니게임 규칙·색상 테마·PNG는 변경하지 않았다.

## 1. 테스트 환경

- Windows (`os.name=Windows 10`, `os.version=10.0`, Java 시스템 속성 기준).
- JDK 17.0.12로 빌드/실행, 기존 Java 8 소스 호환 설정 유지.
- LibGDX 1.13.1 / LWJGL3, NVIDIA GeForce RTX 4060 Ti, OpenGL 4.6.0 NVIDIA 566.36.
- 자동 로직 검증: delta time 1/30, 1/60, 1/120초.
- 실제 GUI: 800×600, 1280×720, 1920×1080 창. 키 입력은 테스트 도구로 주입했다.
- 기존 회귀 검증을 포함하는 `.\gradlew.bat build`를 수정 전/검증 추가 후 각각 실행하여 종료 코드 0을 확인했다. Gradle의 기존 quiet 로그 설정은 유지했다.

## 2. 구조와 전체 진행 흐름

Main이 화면 상태와 입력을 관리하고, StageFactory가 각 학기 실행 데이터를 새로 생성한다. StageResult는 깃발 도착 시 한 번 저장되는 불변 결과다. 모든 학기는 STAGE_CLEAR의 Enter 확인을 거쳐 다음 목적지로 진행한다.

```text
TITLE_SCREEN → Stage 1 → STAGE_CLEAR → Stage 2 → STAGE_CLEAR
→ 카페 INTRO / PLAYING / RESULT → Stage 3 → STAGE_CLEAR
→ Stage 4 → STAGE_CLEAR → 자격증 INTRO / PLAYING / RESULT
→ Stage 5 → STAGE_CLEAR → Stage 6 → STAGE_CLEAR
→ 서버 연결 INTRO / PLAYING / RESULT → Stage 7 → STAGE_CLEAR
→ Stage 8 → STAGE_CLEAR → GAME_COMPLETE 최종 성적표
→ Space → GRADUATION_ENDING → Enter → Stage 1 새 게임
```

새 `FinalIntegrationVerification`은 게임 실행 하나에 Main 인스턴스 하나를 사용하여 위 순서를 끝까지 확인한다. 기존 테스트 체인에 연결했으므로 앞으로도 build에서 실행된다.

연속 흐름 검증의 학기 수집·깃발·낙사는 충돌 지점에 플레이어를 놓는 테스트 픽스처를 사용한다. 이것을 실제 이동 입력으로 모든 맵을 연속 완주한 것으로 간주하지 않는다. 각 학기의 실제 이동·점프·이동 발판·수집 경로는 기존 Stage 1~8 경로 검증에서 별도로 확인했다. 미니게임은 점수·성공 상태를 주입하지 않고 Main.update의 실제 입력 분기를 통해 플레이했다. 재현성을 위해 방학 진입 직후 테스트 모델의 난수 시드만 17로 고정하고, 동작 키 사이에 해제 프레임도 넣었다.

보너스는 `max(0, 20 - semesterDeathCount * 5)`, 최종 점수는 아이템 점수와 확정된 보너스 합계, GPA는 `finalScore / 465.0 * 4.5`다. TOTAL DEATHS를 보너스에 중복 적용하지 않는다.

다음 연속 실행 3종이 30·60·120fps 모두 동일하게 통과했다.

| 시나리오 | 수집 | 누적 사망 | 아이템 점수 | 보너스 | 최종 점수 | 표시 GPA |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 무사망·전체 수집·방학 모두 성공 | 61 | 0 | 305 | 160 | 465 | 4.50 |
| 학기마다 1회 사망·전체 수집 | 61 | 8 | 305 | 120 | 425 | 4.11 |
| 학기마다 1회 사망·1개 미수집·자격증 실패 | 53 | 8 | 265 | 120 | 385 | 3.73 |

기존 학기 결과의 객체가 이후 전환·방학·클리어 화면에서 교체되지 않는지, 아이템 재수집이 거절되는지, 최종 8행/61개/누적 사망이 맞는지 검증했다. 기존 계산 검증은 0~465점 전체와 생존 보너스 0~4회 사망을 포함한다.

엔딩은 반올림 전 점수를 정확히 비교한다. 기존 기준과 정수 점수 경계는 최우수 414점 이상, 우수 362~413점, 일반 310~361점, 간신히 졸업 207~309점, 졸업 유예 0~206점이다. 표시 GPA의 반올림으로 판정하지 않는다. 게임용 GPA이며 실제 대학 성적 계산이 아니다.

## 4. 사망·재시작

기존 LifeSystemVerification, HitFeedbackVerification, SpikeCollisionVerification과 각 맵 경로 검증이 통과했다.

- 적·고정 가시·ACTIVE 시간제 가시의 충돌, 가시 위 허공·받침대·SAFE/WARNING 안전 판정.
- 목숨 2개 이상: DYING 1초 월드 정지, 처음 0.25초 렌더링용 흔들림, 정확히 한 번 차감·사망 집계 후 현재 학기 복원.
- 마지막 목숨: 즉시 GAME_OVER, 중복 차감과 남은 흔들림 없음.
- 낙사: 기존 즉시 처리, 현재 학기 아이템·점수 초기화, 이전 결과·방학 효과 유지.
- GAME_OVER에서는 기록 유지, RESTART는 Stage 1 전체 새 게임, TITLE은 전체 초기화 후 타이틀.
- 새 게임은 모든 StageResult·보너스·사망 기록·방학 기록/효과를 비우고 목숨 5개로 시작.
- 기존 카페 성공 효과는 2학년 각 학기의 시작 목숨 +1이다. 이 경우 6개 목숨이 소진되어야 GAME_OVER가 되는 기존 규칙도 유지·검증했다.
- Stage 8 결과 저장, GAME_COMPLETE/엔딩에서 누적 사망 유지, Stage 9 생성 거절.

## 7. 프레임레이트 및 성능

## 8. 변경 내용과 재현

이번 검증에서 재현된 제품 버그나 명확한 UI 오류가 없어 게임 코드와 아트를 수정하지 않았다. 검증 부족 부분만 보강했다.

- 추가: `core/src/test/java/io/jbnu/test/FinalIntegrationVerification.java` — Main 하나에서 8학기·3방학·성적표·엔딩·초기화와 누적 결과 검증.
- 수정: `FreshmanLevelVerification.java` — 새 통합 검증 실행 연결. 기존 조건은 삭제·완화하지 않았다.
- 추가: 이 문서.

```powershell
.\gradlew.bat build
```

기존 회귀 및 신규 연속 검증이 위 명령에 포함된다. baseline 로그는 `build/integration-baseline.log`, 최종 로그는 `build/integration-final.log`다. GUI 도구별 로그, 측정 코드/로그, 캡처 모음은 `build/integration-gui/`에 있다. GUI 도구와 캡처는 기존 관례대로 Git 제외 build 산출물이다.

## 9. 수동 확인 및 남은 한계

물리 키보드를 직접 조작한 검증은 수행하지 않았다. 다음은 배포 전 사람이 확인해야 한다.

- 방향키 오래 누르기, 반복 점프와 좁은 착지 후 재점프의 조작감.
- Enter/ESC 빠른 연속 입력·누르고 있기, 메뉴 이동+확인 동시 입력.
- 미니게임 중 ESC, RESUME 후 조작 재개와 쟁반/회로/암기 입력의 체감.
- 깃발·DYING 복귀·학기/방학 진입 직후 남은 키 입력의 체감.
- 실제 키보드 동시 입력 제한, 포커스 이동/복귀, 모니터 DPI·전체화면 등 테스트한 세 창 크기 외 환경.
- 실제 사용자에 의한 무중단 8학기 완주와 장시간 반복 재시작·메모리 관찰.

자동화에서는 누른 키와 새 입력을 분리하여 중복 입력·화면 건너뛰기를 검사했다. 실제 키보드 검증이나 사람이 전 학기를 연속 완주한 결과와 혼동하지 않는다. 테스트한 범위에서 미해결 기능 오류는 없다. Git commit, push, merge는 실행하지 않았다.
