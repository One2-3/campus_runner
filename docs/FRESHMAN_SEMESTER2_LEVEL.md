# Campus Runner — STEP 6-3: 1학년 2학기

Stage 2의 테마는 **첫 시험 기간**이다. 낮은 장애물로 시작해, 이동 발판을 관찰하고
탑승하는 한 가지 새 기믹을 익힌 뒤 고정 발판 연속 점프로 마무리한다.
월드 너비는 2600, 시작은 (80,60), 깃발은 (2540,320,20,100)이다.
아이템은 5개×5점으로 최대 25점이며, 함정과 적은 없다.

## 변경 파일과 보존 범위

- `core/src/main/java/io/jbnu/test/StageFactory.java`: Stage 2 분기와 전용 맵 추가.
- `core/src/test/java/io/jbnu/test/FreshmanLevelVerification.java`: 원본 테스트 맵 검사 범위를
  Stage 3~8로 조정하고, Stage 2 전환 시 이동 발판 1개·함정/적 0개·아이템 5개를 기대하도록 수정.
  기존 `verifyFreshman`에서 새 검증도 실행한다.
- `core/src/test/java/io/jbnu/test/Semester2LevelVerification.java`: 새 레벨의 실제 입력 기반 검증.
- `docs/FRESHMAN_SEMESTER2_LEVEL.md`: 설계, 좌표, 검증 및 수동 점검 기록.

Stage 1의 맵·아이템 4개·최대 20점, Stage 3~8의 테스트 데이터는 유지했다.
Player, MovingPlatform, GameState, HUD, 점수 저장, 8학기 진행 코드와 라이브러리는 변경하지 않았다.
GPA는 구현하지 않았다. Stage 1의 기존 설계 기록은 `FRESHMAN_LEVEL.md`를 참고한다.

## Player 물리와 이동 발판 설계

기존 Player는 32×44, 이동 속도 260, 점프 속도 650, 중력 1700이다.
30/60/120fps에서 실제 상승은 113.67/118.86/121.56,
같은 높이 점프 이동은 190.67/195.00/197.17이다.
연속 물리식 기준 상승 한계도 약 124.26, 같은 높이 이동은 약 198.82이다.

중반 바닥 틈은 x900~1480, 폭 580이다. 플레이어 몸체 폭을 더해도 일반 점프로 건널 수 없다.
첫 탑승은 바닥 y60에서 발판 윗면 y120으로 60만큼 상승한다.
출발 가장자리의 x850·870·890에서 발판이 왕복하는 양 방향 모두 탑승을 검증했다.
안전 바닥에서 기다리며 발판을 볼 수 있고, 가까운 끝점과 바닥 사이의 간격은 40이다.

| 이동 발판 항목 | 값 |
| --- | --- |
| 시작 좌표 (왼쪽 아래) | (940,100) |
| 끝 좌표 (왼쪽 아래) | (1300,100) |
| 크기 | 140×20 |
| 속도 | 70 / 초 |
| 편도 거리 / 시간 | 360 / 약 5.14초 |
| 왕복 시간 | 약 10.29초 |
| 탑승면 높이 | 120 |

발판의 전체 이동 영역은 x940~1440, y100~120이다. 양쪽 고정 바닥과 겹치지 않는다.
위에 고정 발판이나 천장이 없어 탑승자 압착 공간도 없다.
기존 MovingPlatform 왕복 계산과 Player의 탑승·이탈·충돌 처리를 그대로 사용한다.
오른쪽 끝에서는 넓은 발판 앞쪽으로 이동한 뒤 y60의 넓은 바닥에 내려선다.
이는 정밀 착지를 요구하지 않으며, 이후 필수 상승은 80·20·80·80이다.

## 고정 발판 좌표

좌표는 (x,y,너비,높이), 왼쪽 아래 기준이다. 바닥을 포함해 총 8개다.

| 구간 | 좌표 | 윗면 | 용도 |
| --- | --- | ---: | --- |
| A | (0,0,900,60) | 60 | 안전한 시작과 이동 발판 관찰·대기 |
| A | (300,60,140,50) | 110 | 첫 낮은 장애물과 아이템 |
| A | (620,60,140,70) | 130 | 두 번째 기본 점프 |
| C | (1480,0,1120,60) | 60 | 이동 발판 하차와 후반 진입 |
| C | (1840,60,160,80) | 140 | 연속 점프 시작 |
| C | (2040,140,160,20) | 160 | 두 번째 착지면 |
| C | (2240,220,160,20) | 240 | 세 번째 착지면 |
| C | (2440,0,160,320) | 320 | 마지막 아이템과 깃발 |

추가 복귀 발판과 장식 발판은 없다. 후반에서 바닥으로 떨어지면 첫 상승 발판부터 다시
진행할 수 있다. 중반 틈으로 추락하면 기존 GAME_OVER와 Enter 재시작을 사용한다.

## 학점 아이템 좌표

모두 24×24, 각 5점이다. 1·2·4번은 기본 경로, 3번은 이동 발판, 5번은 마지막 점프에 대응한다.

| 번호 | 좌표 (x,y) | 수집 위치 |
| --- | --- | --- |
| 1 | (160,84) | 안전한 시작 바닥 |
| 2 | (350,134) | 첫 장애물 윗면 |
| 3 | (1180,144) | 이동 발판에 탄 채 이동하며 수집 |
| 4 | (1710,84) | 하차 후 후반 진입 바닥 |
| 5 | (2490,344) | 마지막 점프 착지면 |

모두 오른쪽 진행으로 수집 가능하다. 자동 부분 수집 경로는 1번 위로 점프해 생략하고
4개·20점으로 클리어한다. 아이템 수집 수는 깃발 클리어 조건이 아니다.
HUD는 기존 `gradeItems.size`를 사용하므로 시작 `ITEMS: 0 / 5`,
전체 수집 `ITEMS: 5 / 5`, `SCORE: 25`가 된다.

## 실제 입력 검증 경로와 결과

새 `Semester2LevelVerification`은 방향키·Space·Enter·ESC를 합성하고 실제 Main.update와
Player.update를 실행한다. Player 좌표·속도·탑승 상태·아이템 상태를 직접 변경하지 않는다.
스테이지 로딩은 정상 loadStage를 사용하며, 연결 검증에서는 Stage 1을 실제 입력으로
20점 클리어한 뒤 Enter로 Stage 2에 진입한다.
기존 FreshmanLevelVerification의 별도 생명주기 테스트에는 과거의 직접 배치 검사가 남아 있으며,
새 Stage 2 완주·실패·재시작 검증은 이에 의존하지 않는다.

좌표의 x는 Player 왼쪽이며 각 도약 후 실제 착지를 기다린다.

- A: x240 → 점프(340,110) → 하강(520,60) → x560 → 점프(680,130)
  → 하강(830,60) → 대기 x870.
- B: 이동 발판 x≤960일 때 점프(1000,120)로 탑승. 발판을 타고 오른쪽으로 이동한다.
  발판 x≥1280에서 앞쪽으로 걸어간 뒤 점프(1510,60)로 하차한다.
- C: x1780 → 점프(1890,140) → x1970 → 점프(2090,160)
  → x2170 → 점프(2290,240) → x2370 → 점프(2490,320) → 깃발 x2540.
- 부분 수집: 첫 아이템 앞 x100에서 (240,60)으로 점프해 첫 아이템을 생략한다.

JDK 17에서 `.\gradlew.bat build` 성공. Java 소스 호환성 8 설정을 유지했다.
기존 `core:verifyFreshman`에 연결되어 다음 항목을 30·60·120fps 모두 검증했다.

| FPS | 전체 수집 / 점수 | 부분 수집 / 점수 | 재시작 후 전체 수집 완주 시간 |
| --- | --- | --- | ---: |
| 30 | 5/5 · 25점 | 4/5 · 20점 | 20.60초 |
| 60 | 5/5 · 25점 | 4/5 · 20점 | 20.77초 |
| 120 | 5/5 · 25점 | 4/5 · 20점 | 20.76초 |

시간은 자동 입력의 대기 시간을 포함한다. 초보자의 관찰·판단 시간이나 실패 횟수를 추정하는 값은 아니다.

- 모든 아이템의 실제 수집과 깃발 클리어, 일부 아이템을 생략한 클리어.
- x850·870·890에서 출발해 양 방향 이동 중인 발판에 실제 착지.
- 입력 없이 12초간 탑승: 상대 위치 유지, 양쪽 끝점 방향 전환, 프레임당 이동 연속성.
- 이동 중 발판에서 점프해 분리된 뒤 같은 발판에 재착지.
- ESC 정지 중 발판 정지와 재개.
- 각 점프 전 다음 착지면이 카메라 범위 안에 있는지 확인.
- 발판이 멀리 있을 때 걷기 및 점프 시도 모두 실제 추락 → GAME_OVER.
- Enter 재시작 시 아이템 5개, 0점, 시작 위치, 이동 발판 시작 위치 복원 및 재완주.
- Stage 1 실제 입력 클리어 → Stage 2 전환·실패·재시작 시 20점 보존.
- Stage 2의 25점 기록 및 Stage 3 진입 시 현재 점수 0점 확인.
- 기존 검증으로 Stage 1과 Stage 3~8 데이터·8학기 진행 회귀 검사.
- StageFactory의 기존 createFreshman/createTestStage 본문과 나머지 실행 코드가
  Git 기준과 동일한지도 소스 비교로 확인.

HUD는 실제 표시 데이터와 기존 표시식을 확인했다. 창을 열거나 렌더링을 실행하지 않으므로
실제 GUI 글자 표시·시인성·체감 난이도는 수동 검증 대상이다.

## GUI 플레이 테스트 항목 (미실행)

`.\gradlew.bat lwjgl3:run`으로 시작해 Stage 1을 클리어한 뒤 Enter로 Stage 2에 진입한다.

- 시작 HUD의 YEAR 1 / SEMESTER 2 / ITEMS 0 / 5 / SCORE 0 확인.
- 안전한 바닥에서 이동 발판의 움직임과 탑승 시점을 쉽게 파악할 수 있는지 확인.
- 탑승·양 끝 방향 전환·이동 중 점프·하차 시 떨림이나 끼임이 없는지 확인.
- 아이템 5개 수집 시 ITEMS 5 / 5 및 SCORE 25 표시 확인.
- 첫 아이템을 점프로 생략해도 클리어 가능한지 확인.
- 중반 추락 후 Enter로 재시작해 아이템·발판·점수가 복원되는지 확인.
- 후반 연속 점프의 다음 착지면과 깃발이 카메라·HUD에 가려지지 않는지 확인.
- Stage 1의 20점 및 Stage 2의 25점 기록을 유지하며 Stage 3으로 전환하는지 확인.
- 초보자에게 Stage 1보다 조금 어려운 정도인지, 관찰 대기 시간이 적절한지 확인.

Git commit, push, merge는 실행하지 않았다.
