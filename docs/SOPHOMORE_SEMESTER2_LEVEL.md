# Campus Runner — Stage 4 난이도 상향

Stage 4(2학년 2학기)는 연속 가시 점프, 수평 발판을 이용한 큰 틈, 좁은 착지면과 추가 점프,
서로 다른 주기의 가시 두 곳, 수직 발판과 높은 깃발을 연결한다.
목표 난이도는 보통+에서 어려움 직전이다. 체감 난이도 확정은 GUI 반복 플레이가 필요하다.
월드 너비 3000, 시작 (80,60), 아이템 7개×5점=35점과 적 없음은 유지했다.
깃발은 (2940,360,20,100)으로 높였다.

## 물리 계산과 난이도 구성

Player는 32×44, 이동 260, 점프 650, 중력 1700이다.
연속 물리 기준 최대 상승은 650²/(2×1700) ≈ 124.26,
같은 높이 체공 시간은 2×650/1700 ≈ 0.765초, 이동 거리는 약 198.82다.
실제 30/60/120fps 측정 상승은 113.67/118.86/121.56,
이동 거리는 190.67/195.00/197.17이며, 맵은 가장 낮은 30fps 성능에서도 통과한다.

- 초반 가시 1·2·3은 따로 점프해야 한다. 첫 두 가시의 간격은 196이고,
  2·3번을 합친 길이도 256이므로 한 번에 모두 넘을 수 없다.
- 세 번째 가시 뒤의 바닥에서 수평 발판을 관찰한다. x1020~1540의 틈은 폭 520으로
  몸체 폭을 포함한 일반 점프 범위를 훨씬 넘는다.
- 수평 발판 탑승은 바닥 y60에서 윗면 y120까지 약 60 상승이며,
  발판이 접근했을 때 넓은 너비 140 위에 착지한다.
- 도착 바닥은 폭 280이다. 가시 4를 피해서 착지한 뒤 폭 120의 다음 틈을 별도 점프로 넘는다.
  가시 4와 다음 바닥을 한 번에 넘으려면 약 320을 이동해야 하므로 진행 점프를 나누어야 한다.
- 후반 가시는 144×72로 두었다. 기존 48 높이에서는 두 번째 함정을 활성 중에도 뛰어넘는 경로가
  검증에서 발견되어 높이를 수정했다. 같은 활성 점프 시도가 이제 두 함정 모두 GAME_OVER가 된다.
  SAFE 때 걸어서 실제 가시 영역을 통과하는 검증도 함께 통과한다.
- 두 번째 가시를 통과한 뒤 짧은 안전 바닥에서 수직 발판에 탑승한다.
  최종 착지면은 바닥보다 300 높아 일반 점프만으로 도달할 수 없다.
- 발판의 편도 이동은 수평 약 3.29초, 수직 약 3.47초다.
  프레임별 이동량은 30fps에서도 각각 약 2.83/2.50이므로 급격한 이동 없이 관찰·탑승할 수 있다.

## 고정 발판 좌표

좌표는 왼쪽 아래 기준 `(x,y,너비,높이)`다.

| 역할 | 좌표 | 윗면 |
| --- | --- | ---: |
| 초반 연속 점프와 탑승 대기 | (0,0,1020,60) | 60 |
| 수평 발판 도착·네 번째 가시 | (1540,0,280,60) | 60 |
| 두 주기형 가시·승강 발판 대기 | (1940,0,500,60) | 60 |
| 높은 최종 착지면 | (2700,340,300,20) | 360 |

바닥 틈은 x1020~1540(520), x1820~1940(120), x2440~2700(260)이다.
마지막 틈에서는 수직 발판 x2500~2640으로 높이 360까지 올라가 마지막 착지면으로 점프한다.

## 가시 좌표와 주기

| 구간 | 좌표 (x,y,너비,높이) | 역할 |
| --- | --- | --- |
| 고정 1 | (420,60,64,24) | 기본 점프 |
| 고정 2 | (680,60,64,24) | 두 번째 독립 점프 |
| 고정 3 | (880,60,56,24) | 이동 발판 접근 직전 점프 |
| 고정 4 | (1690,60,72,28) | 수평 발판 하차 후 신중한 착지 |
| 주기형 1 | (2010,60,144,72) | 주기 관찰 후 통과 |
| 주기형 2 | (2220,60,144,72) | 독립된 통과 시점과 이후 승강 발판 탑승 연결 |

| 함정 | SAFE | WARNING | ACTIVE | 합계 | 초기 오프셋 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 주기형 1 | 1.4초 | 0.6초 | 1.6초 | 3.6초 | 0초 |
| 주기형 2 | 1.1초 | 0.7초 | 2.0초 | 3.8초 | 2.2초 |

첫 함정은 SAFE, 두 번째는 ACTIVE에서 시작한다. 두 함정의 주기와 시작 위상 모두 다르다.
SAFE는 회색, WARNING은 노랑, ACTIVE는 빨강이며 SAFE·WARNING에는 피해가 없다.
안전 대기 위치 x1960, x2170은 캐릭터 몸체 전체가 가시 밖에 있다.
각 함정과 몸체를 완전히 통과하는 시간은 (144+32)/260 ≈ 0.677초다.
각 대기 위치에서 다음 안전 위치까지 약 0.81초이므로 두 SAFE 시간 안에 통과할 수 있다.
두 번째는 더 짧은 안전 시간을 준다. 통과 후 x2380~2400에서 승강 발판 접근을 기다린다.

## 이동 발판

| 종류 | 시작 → 끝 (왼쪽 아래) | 크기 | 속도 | 편도 / 왕복 |
| --- | --- | --- | ---: | --- |
| 수평 | (1060,100) ↔ (1340,100) | 140×20 | 85/초 | 약 3.29초 / 6.59초 |
| 수직 | (2500,80) ↔ (2500,340) | 140×20 | 75/초 | 약 3.47초 / 6.93초 |

수평 발판은 큰 바닥 틈을 건너고, 수직 발판은 높이 차를 극복한다.
수평 전체 영역 x1060~1480은 양쪽 바닥과 겹치지 않는다.
수직 전체 영역 x2500~2640, y80~360에는 고정 지형과 천장이 없다.
최상단에서 최종 발판까지 간격은 60이며 최대 상승 후에는 같은 높이로 점프해 하차한다.
두 발판 위에서 각각 8초간 입력 없이 양 끝 방향 전환과 상대 위치·발 높이 유지 여부를 검증했다.

## 아이템 좌표

모두 24×24, 각 5점이다. 모든 아이템은 고정 지형 및 가시 외곽과 겹치지 않는다.

| 번호 | 좌표 (x,y) | 역할 |
| --- | --- | --- |
| 1 | (160,84) | 쉬운 기본 경로 |
| 2 | (550,84) | 첫 가시 이후 기본 경로 |
| 3 | (810,84) | 두 번째 가시 이후 기본 경로 |
| 4 | (1180,144) | 수평 발판 위 |
| 5 | (2560,264) | 수직 발판 상승 중 |
| 6 | (2170,84) | 두 주기형 가시 사이 |
| 7 | (2860,384) | 높은 최종 구간 |

일반 진행 방향을 따라 전부 수집할 수 있다. 첫 아이템 위로 점프해 6개·30점만 수집해도 클리어한다.
기존 동적 HUD와 점수 저장은 0/7~7/7, 전체 수집 35점으로 동작한다.

## 실제 입력 경로

좌표의 x는 Player 왼쪽이며, 각 점프 뒤 실제 착지를 기다린다.

1. x360 → 점프(550,60) → x620 → 점프(810,60) → x820 → 점프(970,60) → 대기 x980.
2. 수평 발판 x≤1080일 때 점프해 x1120에 탑승한다.
   오른쪽 이동 중 x≥1320에서 앞쪽으로 걷고 점프(1560,60)로 하차한다.
3. x1620 → 점프(1800,60)로 네 번째 가시 회피 → 점프(1960,60)로 짧은 바닥 틈 통과.
4. 첫 함정 SAFE 시작을 기다려 x2170까지 걷고, 두 번째 함정 SAFE 시작을 따로 기다려 x2380까지 걷는다.
5. x2400에서 수직 발판 y≤100을 기다려 점프해 x2540에 탑승한다.
   아이템 높이까지 탄 뒤 x2600으로 이동하고, 상승 중 y≥330에서 점프(2740,360)로 하차한다.
6. 최종 아이템을 지나 x2940 깃발까지 걷는다.

부분 수집은 x100에서 (240,60)으로 점프해 첫 아이템을 생략한 뒤 같은 경로를 이용한다.
점프를 한 번 누른 뒤 계속 누르고 오른쪽으로 이동하는 검증에서는 두 번째 가시에 부딪힌다.

## 자동 검증 결과

신규 경로는 정상 스테이지 로딩과 실제 방향키·Space·Enter·ESC 입력만 사용한다.
플레이어 좌표·속도, 아이템 상태, 함정 위상, 발판 위치를 직접 변경하지 않는다.
이전 Freshman 검증의 직접 배치 생명주기 검사는 유지하지만 새 Stage 4 검증은 이에 의존하지 않는다.

| FPS | 전체 수집·끝점/일시정지 검사 포함 | 부분 수집 |
| --- | --- | --- |
| 30 | 7/7 · 35점 · 42.70초 | 6/7 · 30점 · 25.53초 |
| 60 | 7/7 · 35점 · 41.10초 | 6/7 · 30점 · 25.53초 |
| 120 | 7/7 · 35점 · 40.30초 | 6/7 · 30점 · 25.52초 |

전체 수집 시간에는 각 발판의 8초 안정성 검사와 일시정지가 추가되어 있다.
자동 입력 시간은 사람의 판단·실패·재도전을 포함하지 않는다.

30·60·120fps 모두 다음을 통과했다.

- 실제 입력 기반 전체/부분 수집 클리어와 35점/30점 StageResult 저장.
- 고정 가시 4구간에 각각 실제로 걸어 들어가 GAME_OVER, 첫 가시에 위에서 착지해 GAME_OVER.
- 주기형 2구간의 SAFE → WARNING → ACTIVE 순서·시간 범위·반복 상태 변화, 서로 다른 상태 존재.
- 각 주기형 함정의 활성 중 걷기 및 일반 점프 우회 시도 모두 해당 함정 접촉으로 GAME_OVER.
- 각 비활성 함정 외곽과 실제 겹치는 동안 SAFE·무피해 통과.
- 수평·수직 발판 실제 탑승·하차, 양 끝점 방향 전환, 승강 발판 상승·하강.
- 가시를 모두 넘고 실제 큰 틈으로 걸어 떨어져 GAME_OVER → Enter 재시작 → 전체 경로 재완주.
- 아이템 7개·0점·시작 위치, 두 발판 시작 위치, 함정 6개의 종류·좌표·초기 상태·경과 시간 복원.
- 양 발판 위와 함정 앞에서 ESC 정지·재개: 플레이어·두 발판·두 함정 타이머 모두 정지.
- HUD 입력 데이터의 0~7 개수와 개수×5점 확인.
- Stage 1~3 실제 입력 클리어 결과 20/25/30점 보존, 실패·재시작 후 보존.
- Stage 5 진입, 현재 점수 0점, 앞선 기록과 Stage 4 35점 유지 및 총점 110점.
- 기존 Stage 1~3·Stage 5~8 데이터와 기존 진행 회귀 검사.

JDK 17에서 `.\gradlew.bat build` 성공. Java 8 소스 호환성과 LibGDX 1.13.1 설정을 유지했다.
최종 자동 검증의 미해결 실패는 없다. 기존 검증 조건을 무조건 성공 처리하지 않았으며,
활성 점프 우회가 발견된 구간은 맵 높이를 수정하고 같은 우회 실패 검사와 SAFE 완주를 재실행했다.

## GUI 수동 확인 (미실행)

`.\gradlew.bat lwjgl3:run`으로 Stage 1~3을 클리어한 뒤 Stage 4에 진입한다.

- 초반 3연속 점프와 네 번째 가시 착지의 여유가 충분하며 프레임 단위 정밀 조작을 요구하지 않는지 확인.
- 좁은 대기/착지 구간에서 다음 경로와 가시가 명확하게 보이는지 확인.
- 수평 발판 탑승·하차, 수직 발판 상승·하강·방향 전환의 시각적 안정성 확인.
- 두 함정의 노란 WARNING이 눈에 띄고 서로 다른 SAFE 시점을 관찰할 수 있는지 확인.
- 두 번째 함정 통과에서 승강 발판 탑승으로 이어지는 흐름과 대기 시간 확인.
- 높은 최종 구간의 착지면·깃발이 카메라/HUD에 가려지지 않는지 확인.
- 아이템 7개·35점, 일부 미수집 클리어, 재시작 복원과 이전 학기 점수 보존 확인.
- 여러 차례 반복 플레이로 이전 세 스테이지보다 확실히 어렵고, 어려움 직전 수준이면서 익히면 클리어 가능한지 확인.

Git commit, push, merge는 실행하지 않았다.
