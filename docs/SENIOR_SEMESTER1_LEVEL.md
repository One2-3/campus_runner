# Campus Runner — STEP 6-8: 4학년 1학기

Stage 7은 가시·적 연속 점프, 수평에서 수직 발판으로 직접 갈아타기, 좁고 높이가 다른 착지면,
주기형 가시 세 곳의 독립 통과, 마지막 발판에서 적을 관찰한 하차와 상승 점프를 연결한다.
목표 난이도는 매우 어려움++이다. Stage 6보다 더 많은 연속 조작과 타이밍 결정을 요구하도록 설계했으며,
체감 난이도·반응 여유·시인성은 GUI 반복 플레이로 최종 확인한다.

월드 너비 3800, 시작 (80,60), 깃발 (3760,380,20,100), 아이템 10개×5점으로 최대 50점이다.
순찰형 적 4마리, 고정 가시 5구간, 주기형 가시 3구간, 수평 발판 2개와 수직 발판 1개를 사용한다.

  너비 140·윗면 320의 발판으로 점프한다. 착지 직후 적을 피해 낮은 통로로 다시 점프한다.
  착지 지점과 경로상의 적·가시가 도약 전 카메라 안에 있는지 자동 검증한다.

  함정 사이 바닥은 별도 대기를 허용하므로 서로 다른 주기가 영구적인 통행 불능을 만들지 않는다.

- E: 두 번째 수평 발판으로 폭 440의 틈을 건넌다. 발판과 네 번째 적의 방향을 함께 보고 하차한 뒤
  회피 점프를 하고, 마지막 고정 가시를 넘는 점프를 높이 380의 최종 착지면과 연결한다.
  최종 착지면 자체에는 적이나 즉사 함정이 없다.

## 실제 입력 경로

x는 Player 왼쪽이며 매 도약 후 실제 착지를 기다린다.

1. x200 → 점프(360,60) → 첫 적이 왼쪽 이동 중 x≤460이면 점프(580,60)
   → x590 → 점프(750,60).
2. 첫 수평 발판 x≤860에서 점프해 x900에 탑승한다.
   발판이 오른쪽 이동 중 x≥1010이고 수직 발판 y≤140일 때 앞쪽으로 이동한 뒤 x1280으로 직접 갈아탄다.
3. 수직 발판 아이템 높이까지 탑승 → x1340 → 상승 중 y≥270에서 점프(1480,300).
   두 번째 적이 왼쪽 이동 중 x≤1580이면 점프(1680,300) → 점프(1900,260).
4. 세 번째 적이 오른쪽 이동 중 x≥2120이면 점프(2050,320)로 적과 분리된 왼쪽에 착지
   → 점프(2250,280)로 적을 회피한다.
5. 세 주기형 SAFE 시작을 각각 기다려 x2470, x2690, x2900까지 순서대로 걷는다.
6. 마지막 수평 발판 x≤3000일 때 점프해 x3040에 탑승한다.
   오른쪽 이동 중 x≥3150이고 네 번째 적이 오른쪽 이동 중 x≥3460일 때 앞쪽에서 점프(3400,300)로 하차한다.
7. 점프(3550,300)로 적 회피 → x3560 → 점프(3720,380)로 마지막 가시와 상승 통과 → 깃발 x3760.

세 주기형 가시를 개별 ACTIVE 상태에서 걸어가거나 일반 점프로 우회하면 해당 가시 접촉으로 실패한다.
이와 별도로 SAFE에 실제 가시 영역과 겹치며 통과하는 것을 확인한다.

## 자동 검증 결과

기존 core:verifyFreshman → Stage 2~6 실제 입력 완주 후 SeniorSemester1Verification.verifyConnected()를 호출한다.
새 Stage 7 검증은 정상 로딩과 방향키·Space·Enter·ESC만 사용한다.
플레이어 좌표·속도, 적·발판·함정 위상과 아이템 상태를 직접 변경하지 않는다.
창 없이 실행하기 위한 초기 카메라/viewport 구성 외 런타임 접근은 읽기용이다.
이전 Freshman의 직접 배치 생명주기 검사는 유지하지만 새 Stage 7 경로는 이에 의존하지 않는다.

| FPS | 전체 수집·발판 끝점/일시정지 추가 | 부분 수집 |
| --- | --- | --- |
| 30 | 10/10 · 50점 · 60.40초 | 9/10 · 45점 · 36.13초 |
| 60 | 10/10 · 50점 · 58.27초 | 9/10 · 45점 · 36.13초 |
| 120 | 10/10 · 50점 · 57.23초 | 9/10 · 45점 · 36.16초 |

전체 수집에는 세 발판의 안정성 확인과 일시정지 시간이 추가된다.
자동 시간에는 관찰 대기가 포함되며 사람의 반응·실패·재도전 시간이나 체감 난이도를 나타내지 않는다.

다음 항목을 30·60·120fps 모두 통과했다.

- 실제 입력 전체/부분 경로 클리어, 10개·50점 및 9개·45점의 실제 StageResult 기록.
- 적 4마리의 18초 순찰 범위·몸체 전체 지지·최소 네 번 방향 전환과 프레임별 이동 연속성.
- 적 4마리 각각 실제 접촉 시 GAME_OVER 및 정상 경로에서 점프 회피.
- 고정 가시 5곳 각각 실제 접촉 시 GAME_OVER 및 정상 경로에서 점프 회피.
- 주기형 3곳의 상태 순서·지속 시간 범위·반복 전환과 서로 다른 상태 존재.
- 각 활성 주기형의 걷기/점프 접촉 실패, 각 SAFE의 실제 영역 무피해 통과.
- 수평 2개·수직 1개 실제 탑승·하차와 양 끝 방향 전환 중 안정성.
- 첫 수평 발판 위에서 출발해 수직 발판에 직접 착지하는 갈아타기.
- 너비 100 착지면 위 실제 지지와 적이 있는 너비 140 착지면의 안전한 착지 확인.
- 각 점프 전 다음 착지점과 경로상의 현재 적·가시가 카메라 안에 있는지 확인.
- 실제 큰 틈 추락 후 GAME_OVER → Enter 재시작 → 전체 경로 재완주.
- 재시작 시 아이템 10개·0점·시작 위치, 세 발판 위치, 네 적 위치·방향,
  여덟 가시 종류·좌표·초기 상태·경과 시간 복원.
- 각 발판 위와 함정 앞 ESC 정지·재개: 플레이어·세 발판·네 적 위치/방향·세 함정 타이머 모두 정지.
- 매 프레임 HUD 데이터의 현재 전체 개수 10과 수집 개수×5점 일치, 0~10 모든 수집 개수 관찰.
- Stage 1~6 실제 입력 결과 20/25/30/35/40/45점의 실패·재시작·Stage 8 진입 후 보존.
- Stage 8 원본 아이템 10개와 현재 점수 0점 로드, Stage 7 50점 보존 및 총점 245점 확인.
- Stage 1~6와 Stage 8 원본 데이터 보존, 기존 8학기 진행·결과 회귀 검사.

JDK 17에서 `.\gradlew.bat build` 성공. Java 8 소스 호환성과 LibGDX 1.13.1 설정을 유지했다.
최종 미해결 실패는 없으며 검증 완화·강제 성공·순간 이동은 사용하지 않았다.
기존 물리나 장애물 코드의 수정이 필요한 실제 버그는 발견되지 않았다.
