## 현재 배경 보정: C안, 회청색·채도·대비 (2026-11-07)

현재 기본값은 흰색 필터 대신 C안이다. 아래 흰색 22% 절은 이전 구현 기록이다.

이번 작업에서 Main, 기존 검증 코드, 물리·충돌·맵·점수·목숨·방학 이벤트·원본 PNG는 수정하지 않았다.

| 상수 | 값 |
| --- | --- |

| BACKGROUND_OVERLAY_ALPHA | 0.18 |

기존 중앙 신정문 1회 배치·좌우 확장 슬롯·0.3 패럴랙스·Nearest·공유 텍스처 구조는 그대로다.

### 보정 방식

색상 곱셈만으로 채도/대비를 흉내 내지 않고, 배경 전용 GLSL 셰이더를 한 번 생성해 재사용한다.
배경의 원본 텍스처와 SpriteBatch vertex color를 합성한 RGB에 다음 순서로 보정한다.

1. 밝기값 Y = dot(RGB, 0.2126 / 0.7152 / 0.0722).
2. desaturated = mix(Y, RGB, 0.80).
3. contrasted = (desaturated - 0.5) × 0.90 + 0.5.
4. result = mix(contrasted, #52637B, 0.18).

Alpha는 원본 값을 유지한다. 0.9 대비는 검은 부분을 약간 들어 올리고 밝은 부분을 눌러 준다.
현재 값에서는 RGB 범위가 안정적으로 유지되며, 중앙·선택적 확장·임시 하늘/지면색에 같은 보정을 적용한다.
이 보정은 현재 게임 RGB 공간의 시각적 연출용이며, PNG 파일을 변환하는 작업은 아니다.

배경 pass에만 셰이더를 설정한 뒤, finally에서 이전 ShaderProgram·packed color·블렌딩 활성 여부와
RGB/alpha source/destination 네 factor를 복원한다. 전경과 HUD에는 기존 셰이더를 사용한다.
추가 FBO나 보정 텍스처를 매 프레임 만들지 않는다. 종료 시 배경 셰이더도 dispose한다.
셰이더 생성/컴파일 실패 시 오류를 기록하고 회청색 오버레이만 사용하는 방식으로 낮춘다.
검증한 실제 GL 환경에서는 셰이더가 정상 컴파일되어 C안 전체가 적용됐다.

| 비교안 | 오버레이 | 채도 / 대비 |
| --- | --- | --- |
| A | 흰색 22% | 1.0 / 1.0 |
| B | #52637B 18% | 1.0 / 1.0 |
| C (기본) | #52637B 18% | 0.8 / 0.9 |

공정한 비교를 위해 GUI 도구에서 같은 Stage 7 전경(플레이어·발판·가시·몬스터·아이템·HUD)을 고정하고,
봄 낮/가을 낮/겨울 밤 배경만 바꿨다. 따라서 비교 캡처의 HUD 학기 표시는 세 경우 모두 4학년 1학기다.
실제 게임의 8학기 매핑을 변경한 것이 아니라, 같은 위치·조작 상태를 유지한 진단 픽스처다.
A/B는 GUI 도구가 같은 배경 셰이더의 uniform만 바꾸어 비교하며, 실제 게임의 기본 C 출력과 비교 C가 완전히 같은지도 검사했다.

RGB 범위는 색 강도의 보조 지표이며 HSV 채도 수치 자체가 아니다.
C는 B보다 밝기 표준편차가 약 10%, RGB 범위가 약 27% 작았다.
컬러 비교에서 전경의 초록 발판·금색 아이템과 피부색이 상대적으로 선명하게 남고,
흑백 비교에서는 지붕·창문 등의 배경 명암이 완화되는 것을 확인했다.
겨울 밤 C는 B보다 평균 밝기가 약간 높고, 원본의 가장 어두운 색도 대비 보정으로 들어 올린다.
실제 8개 원본을 별도로 검사해도 모든 계절에서 낮이 밤보다 밝게 유지됐다.
밤 원본의 평균 밝기는 C 적용 후 네 계절 모두 소폭 높아졌다 (겨울 밤 0.3989 → 0.4039, 별도 중앙 샘플).
따라서 지나치게 어둡거나 희미해지는 것으로 판단하지 않았고 초기 C 수치를 그대로 채택했다.

보정은 배경 세부를 지우거나 블러 처리하지 않는다. 아주 작은 가시가 복잡한 지붕과 겹치는 곳은
흑백에서 여전히 시선 구분이 완벽하지 않을 수 있다. 이는 이번 필터가 모든 지형에서 가독성을 보장한다는 뜻은 아니다.

## 이전 배경 파스텔 필터 기록 (흰색 22%, 현재 제거됨)

이번 추가 변경 파일은 SeasonalBackgroundRenderer.java와 이 문서 두 개다.
Main, 기존 물리·충돌·점수·목숨·방학 이벤트, PNG 원본은 변경하지 않았다.

SeasonalBackgroundRenderer.BACKGROUND_WASH_ALPHA = 0.22f 상수로 흰색 필터의 불투명도를 관리한다.
하늘·지면색, 좌우 확장, 중앙 신정문을 모두 그린 직후에 기존 단색용 Texture를 재사용해
전체 배경 시야에 흰색 사각형 한 장을 덧그린다. 새 이미지나 텍스처를 프레임마다 생성하지 않는다.
계절/낮밤과 관계없이 8개 학기에 같은 값을 사용한다.

필터 영역은 배경과 같은 투영 행렬에서 X=viewBounds.x, Y=0, 너비=viewBounds.width, 높이=600이다.
카메라 이동에 따라 영역과 투영 행렬이 함께 이동하므로 화면 전체를 계속 덮는다.
중앙 PNG의 크기·좌표, 신정문 1회 배치, 확장 접합점, 0.3배 패럴랙스는 그대로다.
확장 PNG가 없는 임시 하늘/지면 영역도 같은 필터를 받는다.
필터는 배경 pass 안에서 끝나므로 그 뒤에 그리는 플레이어·발판·아이템·적·가시·HUD에는 덧씌워지지 않는다.

RGB의 의도한 합성은 다음과 같다.

result = background × 0.78 + white × 0.22

배경 pass 동안 정상 알파 블렌딩을 명시하고, alpha 채널은 GL_ONE / GL_ONE_MINUS_SRC_ALPHA로 합성한다.
SpriteBatch의 packed color, 블렌딩 활성 여부, RGB source/destination과 alpha source/destination을
진입 시 저장하고 finally에서 모두 복원한다. 다른 월드/HUD 렌더링에 흰색 tint나 별도 블렌딩이 남지 않는다.
Nearest·공유 Texture·기존 dispose 경로도 유지한다.

현재 준비된 파일은 중앙 PNG 8개뿐이며, 확장 PNG 16개는 모두 없다.
새 이미지를 생성하거나 기존 신정문을 복제해서 확장 이미지를 만들지 않았다.
확장 파일이 나중에 해당 이름으로 추가되면 초기화 때 자동으로 로드한다.

확장 이미지 제작 기준:

- 신정문·정문 지붕·정문 현판을 포함하지 않는 수목·하늘·캠퍼스 풍경.
- 각 학기의 계절과 낮/밤, 중앙 PNG 경계의 색과 풍경을 자연스럽게 연결.
- 권장 크기 2048×768. 다른 너비도 가능하며, 전체 높이를 중앙과 같게 균일 배율로 맞춘다.
- 왼쪽 확장의 오른쪽 끝이 원본의 왼쪽 끝과, 오른쪽 확장의 왼쪽 끝이 원본의 오른쪽 끝과 이어져야 한다.
- 지면/벽돌의 높이와 맨 아래 기준선을 중앙 이미지에 맞춰야 한다.
- PNG 원본의 비율을 유지하고 독립적인 가로/세로 늘이기를 요구하지 않는 구성.

## 중앙 배치와 0.3 패럴랙스

중앙 PNG 원본은 모두 2048×768이다.
월드 높이를 600으로 통일하고 한 가지 배율을 사용하므로 중앙 그림은 1600×600이 된다.

공통 좌표 계산:

- 중앙 그림 X = (stageWorldWidth - 1600) / 2
- 중앙 그림 Y = 0
- 배경 카메라 중심 X = stageWorldWidth / 2 + (worldCameraX - stageWorldWidth / 2) × 0.3
- 배경 시야 높이 = 600
- 배경 시야 너비 = 600 × screenWidth / screenHeight
- 배경 시야 Y = 0

스테이지 중앙에서 배경 카메라와 신정문 중심이 일치한다.
월드 카메라가 오른쪽으로 100 이동하면 배경 시야가 오른쪽으로 30 이동하고,
그림은 화면에서 왼쪽으로 이동한다. 되돌아가면 같은 신정문을 다시 바라보게 되며,
새 건물이나 반복 타일을 생성하지 않는다.

신정문 draw 호출은 매 프레임 정확히 한 번이다.
느린 패럴랙스와 그림 크기 때문에 짧은 스테이지에서는 시작·끝에도 같은 건물 일부가 보일 수 있다.
이는 월드에 여러 건물을 배치한 것이 아니다.
월드 배경이므로 한 화면에는 원본 일부만 보일 수 있지만 원본 전체의 배율은 동일하며 왜곡하지 않는다.

## 좌우 확장과 빈 영역

왼쪽과 오른쪽 확장도 중앙과 같은 배경 투영 행렬에서 그린다.

- 왼쪽 확장 오른쪽 경계 = 중앙 그림 왼쪽 경계.
- 오른쪽 확장 왼쪽 경계 = 중앙 그림 오른쪽 경계.
- 세 그림의 바닥은 모두 Y=0, 높이는 모두 600.
- 확장 너비 = 해당 PNG 너비 × (600 / 해당 PNG 높이).
- 카메라 이동은 공통 투영 행렬에만 적용한다.

각 확장은 한 장씩만 그리며 중앙 신정문을 반복하거나 가장자리 픽셀을 확대하지 않는다.
확장 영역까지 지나면 그 바깥에도 기본색이 남아 빈 공간이 생기지 않는다.

현재는 확장 PNG가 없어 배경 전체를 계절/낮밤에 맞춘 하늘색과 지면색으로 먼저 채운다.
하늘은 Y=0~600 전체를 채우고, 지면색은 Y=0~120에 덧그린다.
중앙 원본과 기본색의 경계가 보일 수 있으며, 이를 완성된 캠퍼스 풍경이라고 보지 않는다.
특히 긴 Stage 7~8의 양끝과 와이드 화면에서 이 경계가 보인다.
자연스러운 나무·캠퍼스 연결을 완성하려면 위의 확장 PNG가 필요하다.

색 채움은 프로그램에서 만든 공통 흰색 1×1 텍스처에 색을 지정한 단색 사각형이다.
원본 배경 PNG에서 가장자리 픽셀을 가져와 늘리는 방식이 아니다.

## 전체 화면·HUD·레이어

배경은 전체 창 viewport를 사용하며 위아래 흰색 여백을 두지 않는다.

| 창 크기 | 배경 월드 시야 크기 | 중앙 PNG 월드 크기 |
| --- | --- | --- |
| 800×600 | 800×600 | 1600×600 |
| 1280×720 | 약 1066.67×600 | 1600×600 |
| 1920×1080 | 약 1066.67×600 | 1600×600 |

배경 다음에 기존 월드 FitViewport를 다시 적용하고, 기존 순서로 모든 오브젝트를 그린다.
월드 카메라 위치, 플레이어 물리, 렌더링용 피격 흔들림과 충돌 좌표는 그대로다.
배경의 벽돌은 장식이고 새로운 바닥이나 충돌체가 아니다.
와이드 창의 기존 게임 월드 시야도 그대로 유지하며 배경만 창 전체에 펼친다.

HUD는 기존 uiCamera 좌표·글자·하트·위치를 유지한다.
밤 배경 위에서도 기존 검은 글자를 읽을 수 있도록 작은 반투명 청회색 받침 두 개만 추가했다.
이 받침은 고정 HUD 투영 행렬에서 그리며, 화면 위아래를 가로지르는 흰 여백이 아니다.
타이틀·방학·성적표·졸업 엔딩 전용 화면의 기존 구성과 전환 규칙은 유지한다.
