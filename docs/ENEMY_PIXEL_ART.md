# 과제 몬스터 픽셀 아트

## 적용 범위

기존 PatrollingEnemy의 도형을 `assets/pixel/enemies/homework_enemy_128.png`로 교체했다.
새 이미지 생성이나 원본 PNG 수정은 하지 않았다.

변경 파일:

- `core/src/main/java/io/jbnu/test/EnemySprites.java`: 공유 텍스처·반전 프레임·렌더링 정렬.
- `core/src/main/java/io/jbnu/test/Main.java`: 렌더러 초기화·SpriteBatch 호출·dispose 연결.
- `core/src/main/java/io/jbnu/test/PatrollingEnemy.java`: 기존 ShapeRenderer 도형 그리기만 제거.
- `docs/ENEMY_PIXEL_ART.md`: 적용 및 검증 기록.

리소스 PNG는 사용자가 준비한 파일이며 이번에 새로 제작하지 않았다.
Git에서 아직 추적되지 않은 `assets/pixel/enemies/` 파일은 그대로 유지했다.

## 원본과 투명 여백

- 원본: 128×128 RGBA PNG, 정적인 한 장.
- 알파가 0보다 큰 실제 그림 범위: X=12~121, Y=13~118 (위에서부터 센 좌표, 양 끝 포함).
- TextureRegion: `(12, 13, 110, 106)`.
- 종이 몸통·손·발·클립·반짝임을 포함하고 외곽 투명 여백만 제외한다.
- TextureFilter.Nearest를 축소/확대에 모두 적용한다.

## 크기와 발 위치

기존 적의 충돌 크기는 실제 스테이지에서 너비 28~32, 높이 32 또는 36이다.
기존 테스트 맵 정의에는 28×28 적도 있다. 어느 경우에도 충돌 사각형을 바꾸지 않는다.

```text
drawHeight = collisionHeight * 1.125
drawWidth = drawHeight * 110 / 106
drawX = collisionX + collisionWidth / 2 - drawWidth / 2
drawY = collisionY
```

| 기존 충돌 높이 | 전체 그림의 월드 크기 (너비×높이, 대략) |
| --- | --- |
| 28 | 32.7×31.5 |
| 32 | 37.4×36.0 |
| 36 | 42.0×40.5 |

발이 포함된 crop의 하단을 기존 적 Y에 맞추고 가로 중심은 충돌 박스의 중심에 맞춘다.
큰 적도 높이가 플레이어의 44단위보다 작다. 그림 전체의 종횡비는 110:106으로 유지된다.
손과 반짝임은 충돌 박스보다 조금 넓게 보일 수 있지만 새 충돌 영역은 아니다.
플레이어와의 접촉은 계속 기존 `player.overlaps(bounds)`로만 판정한다.

## 좌우 반전과 리소스 관리

EnemySprites 하나가 Texture 하나를 로드한다. 정방향/좌우 반전 TextureRegion을 한 번씩 만들고
모든 적·학기·재시작에서 재사용한다. 프레임마다 텍스처나 반전 프레임을 생성하지 않는다.

- 오른쪽: 원본 이미지.
- 왼쪽: 원본을 수평 반전한 이미지.
- 선택 기준: 기존 `enemy.isMovingRight()`.
- 두 프레임의 crop 크기·렌더링 중심·바닥 기준선은 동일하다.
- `update(0)` 및 일시정지/DYING에서는 기존 방향 필드가 유지되므로 그림도 같은 방향을 유지한다.
- 끝점에서 기존 순찰 코드가 방향을 전환하면 이미지만 즉시 반전된다. 좌표 보정은 없다.

로드 실패 시 경로가 포함된 오류를 내고 이미 생성한 텍스처를 해제한다.
게임 종료 시 Main.dispose()에서 EnemySprites.dispose()를 호출한다.

## 렌더링 순서 및 보존한 동작

월드의 기존 투영 행렬을 그대로 사용한다. 별도 카메라 추적이나 위치 반올림을 추가하지 않는다.
고정/이동 발판과 가시를 그린 뒤 몬스터를 SpriteBatch로 그리고, 학점 아이템과 피격 플레이어는 그 위에 그린다.
일반 플레이어의 기존 렌더링 순서는 유지한다. 특히 접촉 후 hurt 이미지는 몬스터보다 앞에 표시된다.
다른 오브젝트의 이미지·HUD·배경 코드는 변경하지 않았다.

다음 로직은 변경하지 않았다.

- PatrollingEnemy 생성자·update·reset·copyInitial·touches와 순찰 방향 필드.
- 적의 수·크기·좌표·순찰 범위·속도 등 StageFactory의 모든 데이터.
- 적 접촉 시 lives > 1이면 DYING, 1초간 hurt 및 월드 정지, 처음 0.25초 흔들림 후 공통 사망 처리.
- 마지막 목숨이면 즉시 GAME_OVER, 타이머/흔들림 없이 목숨 및 사망 카운터를 한 번 갱신.
- 재시작·점수·목숨·방학 효과·GPA·졸업 엔딩.

## 실제 GUI 검증 결과

실제 LWJGL 창에서 Stage 5의 기존 첫 번째 적(충돌 30×32)을 사용했다.
640×480·800×600·1280×720에서 오른쪽 원본, 왼쪽 반전, 일반 피격, 마지막 목숨의 네 상황을 실행했다.
오른쪽→왼쪽 전환은 실제 순찰 update로 끝점에 도달시켜 확인했다.

총 21장: 일반 좌우 순찰 6장, 일반 피격의 흔들림/안정/0.9초/재시작 12장, GAME_OVER 3장.
세 해상도의 대표 캡처를 열어 투명 배경·플레이어 대비 크기·발판 접촉·반전·피격 레이어를 확인했다.

GUI 도구가 함께 확인한 사항:

- 두 반전 프레임이 같은 Texture를 공유하고 U 좌표만 뒤집히며 크기/중심 기준이 같은지.
- Nearest 필터와 학기 전환/재시작 시 EnemySprites 및 Texture 객체 재사용.
- 렌더 중 적의 충돌 크기 30×32 유지.
- 실제 적 접촉으로 DYING 진입, 피격 중 적·플레이어 위치와 적 방향 고정.
- 0.9초에도 hurt 유지, 이후 정확히 한 번 목숨 차감 및 현재 학기 재시작.
- 낙사 네 번으로 마지막 목숨을 만든 뒤 실제 적 접촉 시 즉시 GAME_OVER.
- GAME_OVER에서 타이머/흔들림 0, 전체 사망 횟수 5 유지.
- 게임 종료 후 공통 텍스처의 GL 핸들 0 (해제 완료).

GUI 장면 구성에는 플레이어 위치 초기 배치를 사용한다. 전체 경로의 실제 이동·점프 입력은
기존 8학기 회귀 검증이 별도로 확인한다. 물리 키보드로 전 스테이지를 수동 플레이한 것은 아니다.
