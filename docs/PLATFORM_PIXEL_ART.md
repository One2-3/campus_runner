# Campus Runner — 고정 발판 픽셀 아트 (STEP 10-3-2)

## 변경 파일과 범위

- `core/src/main/java/io/jbnu/test/FixedPlatformRenderer.java`: 잔디/흙 패치 렌더링, 공유 텍스처 로드·Nearest·해제.
- `core/src/main/java/io/jbnu/test/Main.java`: 기존 block.png 렌더링을 고정 발판 렌더러로 연결.
- `docs/PLATFORM_PIXEL_ART.md`: 적용 방식·검증·시각적 제한 기록.

제공된 PNG 원본은 수정하거나 새로 생성하지 않았다.
StageFactory·StageDefinition·모든 고정 Rectangle·Player·MovingPlatform·적·가시·아이템·HUD·배경·미니게임·점수/GPA는 변경하지 않았다.
나무 이동 발판 리소스는 로드하거나 사용하지 않는다. 기존 block.png도 삭제하지 않았다.

원본은 동일한 크기의 완성형 타일이 아니다. 꽃·풀 장식의 높이, 녹색과 흙의 경계,
둥근 바닥/옆면의 투명 영역이 서로 달라 전체 PNG를 단순 반복하면 접합 틈과 높이 차이가 난다.
또한 높이 20인 발판부터 높이 360인 기둥까지 있어 전체 이미지를 각 사각형에 늘리는 방식은 픽셀을 찌그러뜨린다.

## 적용 방식

별도 `FixedPlatformRenderer`가 기존 SpriteBatch 안에서 고정 Rectangle을 읽기만 한다.
모든 원본 픽셀을 동일한 **0.25 배율**로 표시하고, 필요한 재질 패치만 잘라 채운다.
원본 파일을 편집하거나 새로운 합성 이미지를 저장하지 않는다.

| 패치 | 파일 | 원본 X,Y | 원본 너비×높이 | 자연 표시 크기 |
| --- | --- | --- | --- | --- |
| 흙 | center | 40,156 | 224×64 | 56×16 |
| 일반 잔디 | center | 16,20 | 280×96 | 70×24 |
| 긴 바닥 잔디 | long_reference | 300,70 | 400×96 | 100×24 |
| 왼쪽 잔디 | left | 160,70 | 64×96 | 16×24 |
| 오른쪽 잔디 | right | 16,60 | 64×96 | 16×24 |

- 윗부분은 최대 24단위의 잔디 띠로 그린다.
- 폭 480 이상이면 긴 바닥용 잔디 패치를 사용하고 나머지는 일반 잔디를 사용한다.
- 양 끝에는 왼쪽/오른쪽 PNG의 내부 잔디 영역을 최대 16단위씩 겹쳐 표시한다.
- 잔디 아래에 남는 높이는 흙 패치로 채운다. 잔디를 수직으로 반복하지 않는다.
- 마지막 조각이 패치보다 짧거나 낮으면 원본에서 필요한 크기만 잘라 그린다. 전체 패치를 늘려 맞추지 않는다.
- 높이 20인 얇은 발판은 잔디 패치의 위쪽 80픽셀만 20단위 높이로 사용한다. 두꺼운 흙 덩어리를 아래로 넘쳐 그리지 않는다.

좌표는 기존 사각형 안에 한정한다. 잔디 윗면의 렌더링 기준은 정확히
`bounds.y + bounds.height`이며 추가적인 월드 오프셋은 **0**이다.
플레이어의 발 기준도 그대로이므로 서 있는 위치를 바꾸지 않는다.
불투명한 내부 재질로 채운 뒤 가장자리를 겹치므로 원본 외곽의 투명한 홈 때문에 충돌 영역이 비어 보이는 것을 줄였다.
원본 꽃 장식이나 둥근 바닥을 모두 보존하려고 충돌 위/아래로 그래픽을 확장하지 않는다.

## 렌더 순서와 리소스

기존 고정 발판이 그려지던 위치에서 새 렌더러만 호출한다.
발판 뒤의 배경과 발판 앞의 플레이어·이동 발판·적·가시·A+ 아이템 순서를 바꾸지 않는다.
피격 플레이어를 마지막에 그리는 기존 처리와 월드 전용 화면 흔들림도 유지한다.

Main.create에서 렌더러 하나를 만들고 네 grass Texture를 각 한 번 로드한다.
min/mag 모두 TextureFilter.Nearest, SpriteBatch 사용. 각 블록·학기·재시작에서 텍스처를 만들지 않는다.
Main.dispose에서 네 텍스처를 해제하며, 로드 실패 시 이미 로드한 텍스처도 해제하고 해당 경로를 포함한 오류를 보고한다.

## 실제 GUI에서 발견한 제한과 수정

1. 최초 샘플에서는 가장자리 PNG의 잘린 꽃 조각이 일부 발판 윗면에 보였다.
   최종 버전은 장식이 없는 내부 잔디 영역으로 샘플 위치를 옮겨 이 조각을 피했다.
2. 서로 다른 원본에서 가져온 가장자리와 중앙은 녹색 밝기·잎 모양이 정확히 같지 않다.
   일부 연결부의 색상/무늬 변화는 남아 있으며 완전한 무이음 타일이라고 볼 수 없다.
3. 높은 기둥과 긴 바닥에서는 같은 흙 패치가 반복되는 규칙적인 무늬가 보인다.
   픽셀 비율을 유지하기 위한 재질 반복이며, 원본 전체를 높이에 맞춰 늘려 해결하지 않았다.
4. 얇은 발판은 잔디 위주가 되고, 꽃·관목·둥근 흙 밑면 등 원본의 모든 장식을 표시하지 않는다.
   충돌 두께와 다른 긴 그래픽이 아래 지형이나 위험 요소를 가리지 않도록 한 선택이다.

자연스러운 완전 연결과 원본 장식 전체를 함께 유지하려면, 이후 전용 seamless 상단/흙/모서리 타일 리소스가 필요하다.
이번에는 맵 크기나 충돌 사각형을 변경하지 않았으며, 위 제한을 숨기기 위해 다른 오브젝트를 이동하지 않았다.

실제 LWJGL 창에서는 다음 7개 대표 장면을 640×480·800×600·1280×720에서 캡처했다 (총 21개).

- 긴 시작 바닥과 낮은 장애물
- 높이 20인 연속 발판과 발판 위 플레이어
- 높이 360인 최종 기둥
- 고정 가시와 A+ 아이템이 있는 바닥
- 폭 100인 좁은 발판과 주변 적/가시
- 기존 이동 발판이 함께 보이는 장면 (기존 단색 그래픽 유지)
- 실제 오른쪽 이동 입력으로 폭 32 플레이어가 장애물 왼쪽 X=300에서 X=268에 멈추는 측면 충돌

각 장면에서 사각형 배열을 복사해 렌더/물리 갱신 후에도 좌표·크기가 같은지 검사했다.
플레이어 grounded 상태와 서 있는 위치도 확인했다. 일반 장면 위치는 GUI 확인용 배치 픽스처이며,
전체 점프 경로는 기존 입력 기반 회귀 검증이 별도로 확인한다.
학기를 바꿔도 같은 렌더러/Texture를 사용하는지, 네 Texture의 Nearest 필터와 종료 후 GL 핸들 해제를 확인했다.

## 남은 수동 확인 항목

물리 키보드로 직접 플레이하는 수동 검증은 수행하지 않았다.

- 카메라를 따라 이동하며 연결부 색상 차이와 높은 기둥의 반복 무늬가 거슬리는지 확인.
- 실제 연속 점프에서 발끝·잔디 윗면의 접촉감과 얇은 발판의 가독성 확인.
- 다양한 창 크기와 피격 흔들림 중에도 적·가시·아이템이 지형에 가려지지 않는지 확인.

Git commit·push·merge는 실행하지 않는다.
